# 项目维护记录

## 2026-09-26 · 修复 15 秒断线与上游误取消

### 变化

- 根据后台两次精确 `15.0s` 的失败记录确认：不是渠道主动取消，而是浏览器仍采用 IndexedDB 中遗留的 15 秒超时，随后服务端把下游断线联动成了上游取消。
- 生图 API 调用与任务看门狗现在会直接识别同源 `/api/relay/` 地址并强制至少等待 5 分钟，不再只依赖 bootstrap 配置合并，因此旧的本地 profile 超时也无法提前结束托管请求。
- 撤销“浏览器断开就取消上游”的策略；已经提交到渠道的付费任务会继续读完响应，不会再让渠道后台显示“已取消”。本次不向已断开的用户扣积分，但仍如实记录请求。
- 后台错误文案改为“浏览器或前置反向代理提前断开，上游任务未取消”，避免把系统超时笼统说成用户主动取消。
- 应用版本升至 `0.7.11`，确保 Service Worker 获取本轮前端修复。

### 验证

- 生图请求超时、任务看门狗、客户端断线不中止上游和用量统计的 4 个相关测试文件通过：127 个测试全部通过。
- TypeScript 与 Vite 生产构建通过；全量 Vitest 通过：56 个测试文件、932 个测试全部通过。
- 托管模式真机审计通过，后台入口、用量页与应用页面共 0 项失败。

### 经验

- 精确重复的固定秒数通常来自客户端/代理定时器，不是上游随机故障；后台应保留耗时以便直接定位是哪一层超时。
- 付费生成任务一旦被上游接收，就不能简单把浏览器断线传播成上游取消；展示连接和任务生命周期需要解耦。
- 托管模式的安全约束应在实际请求入口再次校验，不能只依赖配置迁移或状态合并。

## 2026-09-26 · 生图等待与用量统计闭环

### 变化

- 托管模式同步生图的前端等待、服务端上游等待统一增加 5 分钟最低保障，后台遗留的 10～30 秒短超时不再提前掐断仍在生成的任务；高于 5 分钟的自定义超时继续保留。
- 服务端下发渠道配置时也会抬高短超时，因此浏览器即使仍运行旧版前端脚本，重新取得 bootstrap 后也能使用安全等待时间。
- 客户端提前断开的调用不再从用量统计中消失：按失败请求记录，但不计为渠道故障，后台可以看到真实请求量且不会误伤渠道健康度。
- 等待上游响应头期间若客户端确实断开，服务端会终止对应连接并完成统计，避免悬挂 Promise 和无记录的后台任务。

### 验证

- 使用用户提供的渠道地址和密钥做了两次真实请求：模型列表包含 `gpt-image-2`；最小请求 24.8 秒成功，携带系统完整参数的请求 26.3 秒成功，均返回 1 张图片，确认渠道、密钥、模型和参数可用。
- 超时投影、中继超时、客户端断开统计、渠道健康度共 4 个相关测试文件通过：134 个测试全部通过。
- TypeScript 与 Vite 生产构建通过；全量 Vitest 通过：56 个测试文件、930 个测试全部通过。
- 托管模式真机审计通过，后台入口、用量页和各应用页面共 0 项失败。

### 经验

- 同步生图接口在返回响应头前可能长时间无字节，文本接口常用的十几秒超时不能直接复用于生图。
- “渠道已经收到请求但后台统计为零”通常不是请求没发出，而是客户端先断开后统计代码主动忽略了该调用；用量与健康度应分开处理，断开要计量但不能归咎于渠道。
- 真实渠道排障应分别验证模型发现、最小请求和产品完整参数，只有三者都成功才能排除渠道适配问题。

## 2026-09-26 · 部署闭环与旧客户端兼容

### 变化

- 确认线上仍出现旧版失败弹窗的根因不是组件残留，而是此前改动只存在本地工作区、未提交到远端部署分支；本次把完整优化提交并推送，服务器更新命令将能拉到真实变更。
- 服务端为 OpenAI 兼容渠道增加请求尺寸兜底：旧页面或旧缓存即使发送 `size: auto`，`images/generations`、JSON `images/edits` 和 Responses 生图工具也会在转发前改为 `1024x1024`。
- 改写请求体后同步重算 `Content-Length`，避免代理仍携带旧长度导致上游截断或等待超时。
- 应用版本升至 `0.7.9`，触发 Service Worker 与静态资源缓存更新，减少发布后继续命中旧界面的概率。
- 增加两条真实 HTTP 中继回归用例，覆盖 Images 与 Responses 两种 `size: auto` 请求。

### 验证

- 中继端到端测试通过：28 个测试全部通过，包含服务端尺寸兜底与请求长度校验。
- TypeScript 与 Vite 生产构建通过；全量 Vitest 通过：56 个测试文件、926 个测试全部通过。
- `audit:menu`、`audit:render`、`audit:server` 三套真机浏览器审计全部通过，均为 0 项失败。

### 经验

- “本地已修改”不等于“服务器可部署”；交付前必须同时确认工作区已提交、远端分支已更新。
- 参数兼容不能只依赖浏览器端修正，面对 Service Worker、CDN 和长期未刷新的页面，付费请求入口还需要服务端兜底。
- 渠道 `INSUFFICIENT_BALANCE` 是上游账号资金问题；“尺寸必须为宽x高”是请求参数兼容问题，诊断和处置不能混为一谈。

## 2026-09-26 · 公网上线稳定性加固

### 变化

- 配置、积分、卡密和作品元数据统一改为耐久 JSON：原子提交后同步 `.bak`，主文件损坏时自动恢复并保留 `.corrupt` 副本；主文件与备份同时损坏时拒绝空库启动。
- 增加公网生图资源闸门，默认限制全站 30 个并发、单账号/IP 2 个并发、每分钟 12 次提交，避免机器人耗尽连接与渠道额度。
- 新增 `/api/health` 独立健康检查和 `X-Request-Id` 响应编号，容器健康检查不再依赖包含业务逻辑的 bootstrap 接口。
- 登录会话改为安全持久化到数据卷，正常发布和容器重启不再让全部用户掉线；改密码、停用账号后的会话失效状态同样持久化。
- 容器更新改为最长等待 120 秒让在途生图完成，减少发布过程中任务被强制中断、上游已出图但用户收不到结果的情况。
- 前台、应用页和后台改为路由级懒加载；主入口脚本由约 1,018 kB / gzip 301 kB 降至约 623 kB / gzip 201 kB，其余页面按需加载。
- `.env.example` 不再内置弱管理员密码，并补充生图限流与优雅退出配置项。

### 验证

- TypeScript 与 Vite 生产构建通过；路由拆包后的所有页面均生成独立产物。
- 全量 Vitest 通过：56 个测试文件、924 个测试全部通过。
- `audit:menu`、`audit:render`、`audit:server` 三套真机浏览器审计全部通过，均为 0 项失败；托管审计额外验证健康检查与请求编号。

### 经验

- 用户资产类数据不能用“文件坏了就空库继续”换取表面可用性；应优先自动恢复可靠备份，无法恢复时失败关闭。
- 公网产品必须在调用付费上游之前限并发和频率，不能把成本保护完全寄托在供应商的 429 上。
- 健康检查应轻量、无认证、无业务副作用；部署退出时间应覆盖真实任务的典型耗时。
- 路由拆包比单纯调高构建警告阈值更有价值，能直接降低首次访问需要下载和解析的代码量。

## 2026-09-24 · 数据安全、代理限流与加载优化

### 变化

- 移除旧版 `DetailModal`：任务失败后继续停留在新版生成结果页，用友好提示和可展开的渠道详情展示错误。
- 修正新创作台默认比例与实际请求不一致的问题：OpenAI 兼容渠道不再收到 `size: auto`，默认发送 `1024x1024`。
- 托管模式只由服务端执行一次渠道故障转移，避免前端再次遍历渠道造成 N×N 重试和重复结算风险。
- 中继不再把“HTTP 200 但没有图片/任务数据”的小型错误响应当成功，不结算失败请求的积分并继续尝试备用渠道。
- 配置或作品元数据损坏时停止启动，防止空配置覆盖账号/渠道，以及孤儿清理误删作品图片。
- 默认不再信任客户端代理头；新增 `GIP_TRUST_PROXY` 显式开关，并在可信模式下避免采用转发链最左侧的伪造值。
- 静态部署统一使用 `Referrer-Policy: no-referrer` 和 `X-Content-Type-Options: nosniff`。
- 修复 bootstrap 已识别托管后端后异常回退成纯前端状态的问题，移除重复邀请参数捕获。
- Service Worker 缓存版本改为从应用版本自动获取，避免手工版本漂移。
- 增加基础 CI、数据损坏和代理 IP 回归测试。
- 新增仓库级 `gpt-image-web-maintainer` skill，固化验证、维护记录和交付格式。

### 验证

- 当前终端未提供 `npm` 命令，直接调用项目内 TypeScript、Vite 完成等价生产构建，结果通过。
- 直接调用项目内 Vitest 完成等价全量测试：53 个测试文件、916 个测试全部通过。
- 直接运行 `audit-menu.mjs`、`audit-render.mjs`、`audit-server.mjs`，三套浏览器审计均为 0 项失败。
- 项目维护 Skill 已生成仓库内清单；官方校验脚本因随附 Python 缺少 PyYAML 无法运行，已按规范人工核对 frontmatter 与 `agents/openai.yaml`。

### 经验

- 元数据无法读取时应失败关闭；任何基于“空索引”的清理都可能把可恢复文件变成永久丢失。
- 只有明确知道请求来自可信反向代理时才能采用代理 IP 请求头。
- 版本类缓存键应从唯一版本源生成，不应在多个文件中手工同步。
- 托管模式的故障转移只能由一个层级负责；前后端同时重试会成倍放大请求、耗时和计费风险。
- 计费不能只依据 HTTP 状态码，兼容网关可能以 200 返回错误对象或空数据。
- “尺寸必须为宽x高”属于请求参数兼容问题；`INSUFFICIENT_BALANCE` 属于上游渠道账号欠费，两者要分别提示，不能统一归因于渠道适配。
