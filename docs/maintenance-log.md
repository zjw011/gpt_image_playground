## 2026-09-26 · 修复 EdgeOne 45 秒回源断线

### 变化

- 根据线上响应头 `EO-LOG-UUID`、`EO-Cache-Status` 与后台精确 `45.0s` 失败记录，确认请求经过腾讯 EdgeOne，前置边缘节点在渠道尚未返回首字节时结束了空闲连接，并非渠道主动失败或 Node 的 5 分钟超时失效。
- 新版托管客户端会为非流式生图请求声明保活；Node 从第 5 秒开始、之后每 10 秒发送一次合法的 JSON 前导空白心跳，穿过 CDN/Nginx 时持续产生响应数据，同时不改变最终图片 JSON 的解析结果。
- 心跳已经开始后，最终渠道错误会包装成完整 JSON 返回，前端可识别真实错误；成功请求会主动重新拉取积分余额，弥补响应头提前发出后无法追加结算回执的问题。
- 增加慢渠道成功、慢渠道失败、心跳错误解析和客户端保活头回归用例；自托管文档补充 EdgeOne `/api/relay/*` 600 秒回源超时与宝塔 Nginx 配置要求。
- 应用版本升至 `0.7.13`，促使 Service Worker 获取新的保活客户端。

### 验证

- TypeScript 与 Vite 生产构建通过；全量 Vitest 通过：57 个测试文件、936 个测试全部通过。
- 慢成功用例确认心跳后的响应仍可由 `response.json()` 解析并正确扣分；慢失败用例确认返回可读错误且积分不变、预留归零。
- 托管模式真机 Chrome 审计通过，健康检查、登录、后台、用量页和各应用页面共 0 项失败。

### 经验

- 线上出现 `EO-*` 响应头且断线耗时为 15 秒倍数时，应优先检查 EdgeOne 的 HTTP 应答空闲超时；浏览器、源站 Node 和 CDN 是三套独立超时，单独放宽应用超时不能解决 CDN 断线。
- 对同步长任务，应用层心跳应早于最短代理超时并携带 `no-transform`、`X-Accel-Buffering: no`；只修改 Nginx 不足以覆盖更外层的 CDN。
- 一旦为了心跳提前提交响应头，状态码和结算头就不能再修改；错误必须在响应体中结构化传递，余额等最终状态需要另行同步。

## 2026-09-26 · 修复 15 秒断线与上游误取消

### 变化

- 根据后台两次精确 `15.0s` 的失败记录确认：不是渠道主动取消，而是浏览器仍采用 IndexedDB 中遗留的 15 秒超时，随后服务端把下游断线联动成了上游取消。
- 生图 API 调用与任务看门狗现在会直接识别同源 `/api/relay/` 地址并强制至少等待 5 分钟，不再只依赖 bootstrap 配置合并，因此旧的本地 profile 超时也无法提前结束托管请求。
- 撤销“浏览器断开就取消上游”的策略；已经提交到渠道的付费任务会继续读完响应，不会再让渠道后台显示“已取消”。本次不向已断开的用户扣积分，但仍如实记录请求。
- 后台错误文案改为“浏览器或前置反向代理提前断开，上游任务未取消”，避免把系统超时笼统说成用户主动取消。
- 应用版本升至 `0.7.11`，确保 Service Worker 获取本轮前端修复。

### 验证
