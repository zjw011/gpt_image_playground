========================================
 得物整点抢兑助手 · 桌面版 使用说明
========================================

【它是什么】
Windows 桌面程序（原生窗口，不是网页）。
主要做两件事：
  ① 抢兑：提前选好商品 → 设定时间（默认每天 10:00:00）→ 到点自动刷新库存
     并抢兑。支持多账号、多任务并行。
  ② 每日答题：活动每天有一道看图猜词题，答对给金币。你填一次答案，
     所有账号依次答完（见下面「每日答题」一节）。
界面为浅色系：浅蓝 + 纯白卡片式布局，卡片带圆角与柔和投影。
抢兑成功后还能自动推送一条微信通知到手机（见下面「微信推送通知」一节）。

【快速开始 3 步】
------------------------------------------------
1) 双击 dist\得物整点抢兑助手.exe，程序窗口直接打开。

2) 【01 账号管理】导入账号 —— 两种方式，任选其一

   ★ 方式 A（推荐，v1.5 新增）：点「手机号登录 · 免抓包」
     不用装抓包工具，也不受输入法粘贴长度限制，直接输手机号 + 密码登录：
       ① 点按钮 → 弹出登录窗
       ② 填手机号 + 密码（备注名可留空；活动 ID 一般不用改）
       ③ 点「登录并添加」，约 1~2 秒后账号自动加好

     · 登录走的就是得物客户端自己的登录接口，两处客户端加密已复现：
         userName = AES-128-ECB(手机号, 密钥 "mobile0123456789") + "_1"
         password = md5(明文密码 + "du")
     · 密码只在本机做哈希后发出，工具不会保存你的密码。
     · 登录态有效期约 365 天 —— 登录一次能长期用，不用反复弄。
     · 若提示「登录被拒绝 / 请稍后重试」，多半是内置的设备指纹头过期了：
       用方式 B 重新抓一次包导入，工具会记住新抓包里的设备头。

   ☆ 方式 B（备用）：粘贴抓包 curl
     在手机 App 抓包，复制那条「商品列表」请求的完整 curl
     （形如 .../gameplay/branch/exchange_list?activity=... 的 GET 请求），
     粘贴到输入框 → 点「导入账号」。备注名可留空。
     ※ curl 里至少要有 x-auth-token 请求头（Cookie 有更好）。

   两种方式公用说明：
   ※ 多个账号：每个账号分别导入一次。工具按 x-auth-token 自动去重 ——
     同一个账号无论用抓包还是手机号登录导入，都只会【更新】不会重复建账号。
   ※ 【活动换了怎么办】工具完全按导入时的链接发请求（activity 原样使用，
     不会自己按日期重算）。若提示「当前活动不存在 / 活动已结束」，说明这场
     活动结束了：重新进入新的活动页（方式 A 点进活动页 / 方式 B 重新抓包）
     再导入一次即可，同一账号会自动更新为最新链接（会弹提示）。

3) 【02 商品列表】点「刷新当前」拉取商品与金币余额
   表格列：等级 / 商品名称 / 所需金币 / 库存 / 状态
   ※ 【缺货的也会全部列出】列表显示接口返回的**全部商品**，不做任何过滤。
     并且【照样可以点选、照样能建任务】—— 这正是抢 10 点补货的关键：
     提前把缺货商品选好，到点工具会先刷新库存再抢兑。
     标题栏会写明「共 N 个 · 可兑换 M · 缺货 K」，方便核对有没有漏显示。

   ※ 三种状态的配色（一眼区分）：
       可兑换 —— 金币蓝色、状态「可兑换」绿色      → 现在就能换
       缺货   —— 整行灰字、库存「0」与「缺货」红色  → 当前没货，10 点补货后能抢
       未解锁 —— 整行浅灰、状态「未解锁」          → 等级不够，真的不能换
     判定口径：接口的 outOfStock 标志 **或** 库存 ≤ 0，两者任一成立即视为缺货
     （实测有商品库存为 0 但标志仍是 false，只信标志会漏掉）。

   点击任意一行即选中为兑换目标。

4) 【03 新建定时任务】
   目标时间  默认 10:00:00（每天补库存的时刻）
   提前发起  默认 300 毫秒，即 09:59:59.700 开始发请求
   重试间隔  默认 200 毫秒
   最大尝试  默认 600 次（另有 180 秒总时长上限保护）
   每日重复  勾选后当天失败会留到第二天同一时间继续
   点「创建任务」后可在【04 任务监控】看状态。

   ※ 【倒计时看得见】任务建好后不用干等：
     · 【04 任务监控】的「详情」列会实时显示「倒计时 3 分 20 秒 · 10:00:00」；
     · 运行日志会自动打点：剩余 30 / 10 / 5 / 2 / 1 分钟各一条，
       剩余 30 秒一条，最后 10 秒逐秒倒数（倒计时 10 秒…9 秒…），
       到点再打一条「⏰ 时间到，开始刷新库存并抢兑」。
     所以只要看到日志在倒数，就说明任务运行正常，不用守着屏幕。

   ※ 【商品下架/失效会立刻停手，不再空刷】
     如果你刷新商品后，原来配置的那个商品已经不在列表里（下架、换批次、活动结束），
     任务不会再傻刷几百次把当天机会耗光：
       · 到点时会先用最新列表核对一遍：商品确实不在 → 一次兑换请求都不发，
         直接判失败，日志写「配置的商品已不在列表中（已下架或售罄），开抢前已停止」；
       · 如果抢到一半商品被下架，连续 2 次收到「商品不存在」也会立即收手
         （日志会写「只试了 N 次，没有空刷」）。
       · 以上都算「配置已失效」→ 任务直接停掉（不会再留到明天）。
         请到【02 商品列表】刷新后重新选商品，再建一个新任务。
     ✔ 顺带好处：如果商品还在、只是活动换了批次导致 cId 变了，程序会按商品名
       自动重新匹配（cId / skuId 自动换成新的），你不用重建任务。
     ⚙ 想让「商品没了也每天继续试」，把 config.json 里的 stop_on_gone 改成 false。

   ★ 【自动降级兜底：商品没了就自动换一个（默认开）】
     活动快结束时商品会一批批下架，最亏的就是守着一个已经没了的商品白等到 10 点、空手而归。
     所以新建任务时默认勾上了「失效自动降级」：

       · 触发时，程序会在【有货】且【价格 ≤ 金币余额】的商品里挑**最贵**的那个顶上；
         价格相同的，取商品列表顺序第一个。
         例：你号上 110 金币，配置的商品没了 → 自动换成 108 金币那个。
       · 每个任务**最多降级一次**，不会一路换到最便宜那个（那等于清空金币）。

     ⚠ 先说清楚：这个功能等于「尽量把金币花出去」，和「没抢到就把金币留着」正好相反。
       不想要就在【03】里取消勾选「失效自动降级」，或者在「降级设置」里整个关掉。

     三个触发条件（各自独立，在「降级设置」里勾）：
       商品下架就换     配置的商品从列表里消失（下架 / 活动换批次）→ 立刻换   （默认开）
       抢不到也换       到点了商品还在但一直售罄、刷满次数也没抢到 → 换        （默认开）
                        ※ 会牺牲掉「继续等它补货」的机会，所以慎用
       余额买不起也换   配置的商品价格超过余额 → 换成买得起的那个          （默认关）

     价格门槛（「降级设置」底部下拉）：
       不设门槛（默认）      买得起里最贵的就是它，哪怕活动末期只剩便宜货也换
       不低于原价 50%        低于原价一半就不换，任务按失败停
       不低于原价 80%        只接受和原商品价位接近的替代品

     怎么用：
       ① 全局默认值：点【03】右上角「降级设置 · 开」→ 勾触发条件 + 选门槛 → 保存
       ② 单个任务：【03】里的「失效自动降级」勾选框，建任务时决定这个任务要不要兜底
          （取消勾选 = 老行为：商品没了就直接失败停手）
       ③ 事后能看出来：
          · 任务列表里，被降级过的任务【商品】列前面会带「降级·」前缀、整列标成橙色，
            鼠标停上去能看到「原配置：XXX / 已自动降级为：YYY」
          · 【详情】列会补一句「已降级换商品」
          · 运行日志里有「↩ …… → 自动降级换商品：『原商品』→『替代品』金币N（同价位取列表顺序第一个 · 余额 M）」
          · 微信推送卡片底部会红字写明「⚠ 原配置的『XXX』已失效或抢不到，本单是【自动降级】后换商品抢到的」

     ⚙ 配置在 config.json 的 fallback 段：
       enabled / on_gone / on_soldout / on_poor / min_ratio
       已建好的老任务会在启动时自动补上这段（用当时的全局默认值）。


【微信推送通知（抢兑成功自动推到手机）】
------------------------------------------------
用途：不用守着电脑。任务抢到以后，微信立刻收到一条卡片式通知。

怎么开（3 步）：
  1. 点窗口右上角「推送设置 · 未设置」
  2. 弹出设置窗，把 PushPlus 的 token 粘进「Token」框
     · 还没有 token？点右边的「去获取」，微信扫码登录 pushplus.plus，
       复制「一对一推送」里那串 32 位 token
  3. 勾上「开启抢兑成功推送」→ 点「保存」
     按钮变成「推送设置 · 已开启」就说明生效了

  ※ 想先确认能不能收到：先点「发送测试」，微信马上会收到一条示例通知。
    看到示例再保存，最稳。

推送的卡片里包含：
  · 账号备注（你在账号管理里填的那个名字）
  · 兑换的商品名称
  · 兑换结果（成功 / 失败）
  · 消耗金币
  · 剩余金币（成功时用醒目的红字突出）
  · 完成时间（精确到秒）
  · 任务编号 + 第几次尝试抢到的

  样式上：成功是蓝色渐变头 + 绿色「✓ 兑换成功」徽标；
          失败是橙色渐变头 + 橙色「× 兑换失败」徽标。

  ※ 失败也想收到通知？在同一个弹窗里勾上「抢兑失败也推送」。
    默认只在抢到时推送，避免吵。

几点说明：
  · token 只写在本机 config.json，除了 PushPlus 官方接口不会发给任何地方。
  · 推送是【后台异步】发的 —— 不会占用那 600 次连发的时间，绝不拖慢抢兑。
  · 推送万一失败也不影响抢兑，只在【05 运行日志】留一条「[推送] ✗ …」。
  · 想临时停掉：打开设置窗，取消勾选「开启抢兑成功推送」再保存（token 留着）。
  · 想彻底清掉：把 Token 框清空后保存即可。
  · 收不到消息时，先点「发送测试」：返回的报错原文会直接显示在弹窗里
    （常见的有「用户令牌不正确」= token 抄错了；额度用完也有明确提示）。


【每日答题（一键答完所有账号）】
------------------------------------------------
用途：这个活动每天还有一道「看图猜词」题（谐音梗），答对给金币。
     题目是图，只有人能看懂，所以由你填答案 —— 但多账号不用一个个点，
     填一次，所有账号依次答完。

入口：窗口右上角「每日答题」按钮，会自己显示今天的状态：
        「每日答题 · 待答」  = 今天还没答，点进去
        「每日答题 · 已答」  = 今天已经答对了，明天再来

怎么用（3 步）：
  1. 点「每日答题」，弹窗会自动取到【今天的题目图】和提示
     （提示会写清楚：答案是几个字、是什么类型，比如「3 个字 · 谐音」）
  2. 看着图，把答案填进「今日答案」框
  3. 点「一键答题」→ 所有账号依次作答，表格里逐行出结果

结果怎么看（表格三列）：
   账号   你填的备注名
   结果   绿字「答对，+1 金币」/ 红字「答案不对，还剩 N 次机会」/
          灰字「今日已答对，跳过」
   余额   答对了会显示变化，比如「60 → 61」

它替你处理的几件事：
  · 题号（questionId）每天都不一样的，程序自动取，不用你管
  · 今天已经答对的账号会自动跳过，不浪费次数
  · 你填的字数和提示对不上时会先弹窗确认（防止手滑填错）
  · 答完立刻刷新金币余额，账号列表上的数字同步更新

题目长什么样（以 2026-09-19 那题为例）：
  图上半张：「这是芒果。」（给个参照）
  图下半张：一只小狗在石臼里捣芒果，下面写「这是＿＿＿」
  答案：捣芒犬 → 谐音「导盲犬」（3 个字）

几点说明：
  · 程序不做「自动猜题」。瞎猜会把当天次数浪费掉（每题每天最多 3 次机会，
    答对即得金币），所以答案由你看图填写，这是最稳的。
  · 答题用的是账号自己的登录态，和你导入的抢兑账号是同一套，不用额外配置。
  · 题图没加载出来可以点「刷新题目」重试；也可以直接对着手机上的图在这边填。
  · 每天只给一次「答对」的机会（答对后当天不再加分），表里会显示「今日已答对」。


【库存监听（新品上架 / 补货 就推微信）】
------------------------------------------------
用途：不用一直盯着商品列表。程序按固定间隔帮你查一遍，
     发现「冒出新商品」或者「原来缺货的又有货了」，立刻推一条微信给你。

入口：窗口右上角「库存监听」按钮，会自己显示状态：
        「库存监听」          = 没开
        「库存监听 · 运行中」  = 正在监听（鼠标停上去能看到用哪个号、间隔多少、监听了几个）
        「库存监听 · 已开启」  = 开关开着但线程没跑，点进去重开一下即可

怎么开（3 步）：
  1. 点「库存监听」打开设置窗
  2. 勾上「开启库存监听」，按需调「检查间隔」（默认 30 秒）
  3. 点「保存并应用」→ 按钮变成「库存监听 · 运行中」

弹窗里各栏什么意思：
  监听状态     ● 正在监听 · 每 N 秒一次 / ○ 没在监听
  监听账号     只用一个号去拉商品列表（下面「监听账号」下拉里选的那个）
  已监听商品   当前记住了多少个商品；第一次开启会显示
               「还没建立基线（开启后第一次检查会建）」
  上次检查     最近一次成功拉到列表的时间
  已提醒商品   累计推了多少件变化
  最近错误     拉列表失败时的报错原文；成功一次就自动清零

  检查间隔     5 ~ 3600 秒。太密容易被风控，建议 30 ~ 60 秒
  监听账号     建议挑一个不参与抢兑的号，或者抢兑任务里用得最少的那个
  新品上架提醒 列表里冒出新商品且有货 → 推一条
  补货提醒     原来缺货 / 售罄的商品又有货了 → 推一条

  立即检查一次 不等定时器，马上拉一次列表做比对（拿来验证配置对不对）
  样式预览     用浏览器打开推送卡片的样式预览（含新品 / 补货两种）
  保存并应用   把上面这些参数写进 config.json 并按新的开关启停监听

它替你处理的几件事：
  · 第一次开启只「建立基线」，不推送 —— 否则一开启就会把整页商品推一遍
  · 缺货的新品不算「新品上架」。等它真有货了才算，省得白高兴一场
  · 判断有没有货时，同时看接口的 outOfStock 标志和库存数
    （实测有商品 stock=0 但标志是 false，只看标志会漏）
  · 手动「立即检查一次」和后台定时检查不会同时跑（内部加了锁），
    同一个变化不会推两遍
  · 拉列表失败不刷屏：第 1 次和第 10、20… 次各记一条日志，恢复后自动清零
  · 关掉窗口 / 退出程序，监听线程会立刻退出，不留后台空转

推送的卡片里包含：
  · 监听账号备注 + 商品名称 + 所需金币 + 当前库存
  · 每件的标签是 🆕新品 还是 🔔补货
  · 顶部标题按类型变色：纯新品=蓝色「新品上架」、
    纯补货=绿色「有货了」、混着来=灰蓝「库存变化」
  · 一次超过 12 件会截断，只推前 12 件并在末尾提示「还有 N 件…」

几点说明：
  · 监听只「拉列表」，绝不会自动下单、不会抢兑，纯提醒。
  · 商品列表跟着账号所属活动走：同时盯着多个活动就换个对应的号来监听。
  · 没配 PushPlus token 也能开监听，但只在【05 运行日志】留痕、不发微信；
    弹窗会红字提醒你去「推送设置」补 token。
  · 上次退出时监听是开着的，下次启动会自动接着监听（不用手动开）。
  · 想临时停：打开弹窗取消「开启库存监听」→「保存并应用」（已记的快照保留，
    下次开启接着比对，不会从头再来）。

【窗口大小（笔记本必看）】
------------------------------------------------
程序启动时会自动读取当前屏幕的可用区域（已扣除任务栏），
按屏幕大小算一个合适的窗口尺寸并【自动居中】，不会再超出屏幕。

  · 窗口大小、位置会记住：下次打开回到你上次调整的位置和尺寸。
    换显示器 / 改分辨率后如果位置不对，点右上角「适配窗口」一键复位。
  · 窗口可以自由拖拽缩放，最小 1010 x 520。
  · 屏幕较矮时（如 1366x768）内容区会出现竖向滚动条，滚动查看即可。
  · 声明条是一条 26px 的细条，固定在窗口【最顶部】，不随内容滚动、
    也不会遮住下面的任何卡片。
  · 换了显示器后若窗口跑到屏幕外，程序会自动检测并拉回主屏居中。


【屏幕不够高？这样腾地方（笔记本推荐）】
------------------------------------------------
笔记本屏矮，为了让「商品列表」始终看得见，纵向空间是这样分配的：

  · 账号管理：操作按钮全部收进标题栏，表格高度随账号数量自适应
    （2~5 行，账号少的时候不白占地方），多了在表格内部滚动。
  · 商品列表：有高度下限，任何窗口尺寸下都至少完整显示 5 个商品，
    其余商品在表格内部上下滑动查看。
  · 账号区右上角有「收起 / 展开」按钮：点「收起」把账号区压成一行，
    商品列表立刻多出一大截空间；需要看金币余额时再点「展开」。
    这个状态会记住，下次打开保持你上次的选择。
  · 默认打开时账号区是展开的。嫌挤就先点一下「收起」。


【★ 测试兑换（诊断）按钮】
------------------------------------------------
位置：【02 商品列表】右下角。正式抢购前用它确认账号状态。
它依次做三件事，过程完整写入【05 运行日志】：

  ① 检查请求头    Cookie / x-auth-token / duToken 是否齐全
  ② 验证登录态    用列表接口确认 token 有效，并读回当前金币余额
  ③ 探测兑换接口  发一次真实兑换请求，读服务端返回并给出判定

判定结果会显示在按钮下方的彩色结果条：

  ✅ 兑换链路完全正常 · 仅余额不足       一切正常，余额够时就能抢到
  ✅ 兑换链路完全正常 · 兑换成功         参数与库存没问题（会真实扣金币）
  ❌ Token 失效 / 被风控拦截（请先登录）  重新抓包导入，或等几分钟再试
  ⚠️ 参数不合法（code=900）             活动或商品参数变了，需重新抓包
  ❌ 活动已失效 / 不存在（110000003）    这场活动结束了，重新抓新活动的包并导入
  ⚠️ 登录态正常但商品列表为空            活动可能已结束
  ❌ 网络异常                            本机网络 / 代理问题

【安全机制】诊断默认走「安全模式」：自动挑一个金币余额买不起的商品去探测，
服务端只会返回「余额不足」——这恰好证明 token、参数、链路全部正确，
同时又不会真的扣金币。只有当余额足以买下列表里所有商品时，
程序才会弹窗警告，由你决定是否继续（那种情况会真实下单）。


【几个重要提醒】
------------------------------------------------
1. 得物有风控。短时间密集请求会触发「请先登录」软拦截，通常几分钟后自动
   恢复。所以：不要反复点「测试兑换」；正式抢购用默认 200ms 间隔即可。
   若一直 700，请在手机 App 正常打开活动页逛一圈，再重新抓包导入。

2. accounts.json 保存着账号登录凭证（等同于密码），
   请不要把这个目录打包发给任何人。

3. 时间准确性很关键。开机后先点右上角「校时」对比阿里云 NTP，
   误差超过 200ms 建议在 Windows「设置 → 时间和语言 → 立即同步」。

4. 数据文件（均在 exe 同目录）：
   accounts.json    账号与登录凭证
   tasks.json       任务列表（重启程序自动恢复未完成任务）
   config.json      默认参数
   watch_state.json 库存监听的商品快照（记住上次看到啥，才能比出「新品 / 补货」）
   dewu_sniper.log  运行日志（排查问题用）

   （v1.5 起不再使用浏览器，上面的 browser_profile 目录可以删掉。）

【关于图标（改图标必看）】
------------------------------------------------
   一个 exe 其实有「两个图标」，别搞混：
     ① 文件图标：资源管理器里看到的那个，来自 exe 的 PE 资源，由 --icon 决定；
     ② 窗口图标：任务栏 / Alt+Tab 看到的那个，来自程序运行时调用的
        QApplication.setWindowIcon()，需要**运行时读得到 app.ico 文件**。

   ★ 所以 spec 里这行不能少（datas 里必须带 app.ico）：
         datas=[(APP_ICO, '.')]
     onefile 模式下 _MEIPASS 和 __file__ 指向的都是解包临时目录，
     不写进 datas 就永远找不到 app.ico → 图标为 null →
     任务栏 / Alt+Tab 会显示成 Windows 系统默认图标（一个绿色窗格的图标）。
     只给 --icon 的后果就是：文件夹里图标好好的，任务栏却是默认图标。

   app.ico 由 build_icon.py 生成，不能直接用图片另存为 ico。
   原因：Windows 资源管理器只对 256x256 允许 PNG 压缩帧，
   16/24/32/48 等小尺寸必须是 BMP/DIB 裸位图，否则文件夹里
   会显示成系统默认的空白 exe 图标。
   build_icon.py 会按尺寸分别写 DIB / PNG，并生成 icon_preview.png 预览。

   换新图标素材：把图片放到 icon_src\ 下，改 build_icon.py 顶部的 SRC 路径，
   运行 python build_icon.py 后重新打包。

   若文件夹里仍显示旧图标，是系统图标缓存未刷新，执行一次：
       ie4uinit.exe -show
   然后按 F5 刷新文件夹。
